I spend most of my time learning the fundamentals and understanding what good software looks like. I’m no longer focused on constantly chasing new tech stacks, libraries, frameworks, or languages. That doesn’t mean I don’t know how to program, but I don’t think it’s necessary to follow every new stack that comes out each week.

Instead, I believe the most valuable skill is having engineering taste. It’s about knowing what good code and software look like, and choosing the right architecture to solve problems efficiently. I’d rather spend time understanding how microservices work and what trade-offs to consider, instead of just learning how to write a loop in Go. I want to understand how Go compiles and what happens behind the scenes, not just focus on basic syntax like if or else statements.

Before this, most of us learned software engineering by starting with coding. We spent a lot of time in university learning tools that the job market demands. I’m not saying libraries, frameworks, or languages will disappear, but they shouldn’t take up most of our time. You don’t need to memorize how to write a loop in every language. You just need to understand what a loop is, how it works, and when to use it. If you understand it deeply, you can write it in any language.

Some languages are especially good for learning deeper concepts. For example, Rust helps you understand how memory works and how to manage it safely. But it’s important not to lose sight of why we learn programming in the first place. Programming is the entry point into the engineering world. It’s the first step for anyone who wants to become a software engineer.

AI is just a tool, like a programming language, a library, or a framework. All of these were created to solve problems developers faced. Go was created at Google to improve compile times compared to C++. Rust was designed to address memory safety. In the same way, AI helps reduce bottlenecks in the [[Software Development Life Cycle| SDLC]]. In the past, writing code took a lot of time. Design was also hard and time-consuming, but coding was a major bottleneck because everything had to be written by hand, and bugs were unavoidable.

AI helps reduce the time spent writing code, but it doesn’t replace thinking or judgment. It speeds up execution, not decision-making. I agree that AI is powerful, but I still believe in human thinking. AI can make us better, but only if we know how to use it well. People say to use AI as a second brain, but you can’t have a second brain if you don’t have the first one.

In this decade, AI has made writing code cheaper than ever. That means we need to push ourselves to deliver the best software we can, because coding is no longer the main bottleneck. I’m not saying programming isn’t important. You still need to know how to code so you can evaluate and use AI-generated code effectively.
